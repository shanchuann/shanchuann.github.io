同一个需求

原话

帮我做个下拉，能选负责人

AI 自己猜形式、猜操作规则。猜错一次，返工一次。

规格

负责人用 Select 单选下拉：选项为团队成员、单选、选中打勾、可清空重选、点外部或 Esc 关闭

形式与操作规则一次到位，交付可以复核。

效果预览

登录页分屏表单

左右分屏的登录页 左侧讲品牌，右侧放表单

图表选型汇总

从上往下读的经营报告 先结论，再趋势，最后原因

下拉单选筛选

能选负责人的单选下拉 选中打勾，可清空重选

导航吸顶移动端

滚动后收窄的导航栏 桌面悬浮吸顶，移动端沉底

轮播拖拽回正

按住拖动的轮播 松手回正，键盘也能操作

二次确认输入校验

输入文字才能删除 输入一致之前，按钮不可用

空状态引导

首次使用的空页面 给创建和导入两条路

工作流

  1. 01

    识别需求类型

    控件、布局、交互规则、修复、图表，先归位，再读对应的参考文件。

  2. 02

    列候选，写理由

    下拉 7 种、进度 8 种、导航 9 种，用途各不相同。给出 2 至 3 个候选和适用场景，信息不足就先问。

  3. 03

    留下选型笔记

    候选对比、判断依据、升级条件写进 notes.md。过程可复核，交付可验收。

  4. 04

    输出规格

    按名称、形式、操作规则的固定顺序给出 Prompt，或直接按规格生成页面。

差距落在选型过程

5 个失败项里，4 个是没写候选对比与选型理由。裸跑直接给实现，过程不可复核；带技能的产出把判断依据留在了 notes.md 里。

隐性规则决定对错

空状态一题，裸跑把搜索无果做成了提示加大按钮，还加了新建客户这个会把用户带向错误动作的入口。带技能按搜索改关键词、筛选改条件的规则处理。

安装

TERMINAL
# 交互式安装，自动识别已装好的 agent
$npx skills add shanchuann/better-web-controls
# 只写到 OpenCode
$npx skills add shanchuann/better-web-controls -a opencode
# 全局安装，跨项目可用
$npx skills add shanchuann/better-web-controls -g
  • 01环境。Node.js 22.20 以上。skills CLI 支持 75 个以上的 agent。
  • 02落位。安装时写入对应 agent 的技能目录：OpenCode 为 .opencode/skills/，全局为 ~/.config/opencode/skills/，不用手动放。
  • 03更新。技能发版后执行 npx skills update 即可。

两种用法

用法一：翻译

把模糊需求翻成规格

描述你想要的页面或控件，做个下拉、导航好看点都行。agent 给出候选、选型理由和可以直接用的 Prompt。

看工作流 用法二：生成

按规格直接出页面

规格已经明确时，agent 按名称、形式、操作规则生成单文件 HTML。截图里的七个页面都是这么出来的。
