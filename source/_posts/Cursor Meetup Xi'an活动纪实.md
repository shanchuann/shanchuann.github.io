## 上半场：从代码优化到思维重构

### 00 后开发者：深入使用Cursor进行C++编程

![cursorC__.jpg](https://s2.loli.net/2025/09/20/o5nIhwXPGxpR9B3.jpg)

首位分享者是一位 00 后 C++ 开发者，他开门见山抛出核心观点："Cursor 的 AI 辅助编程模式，早已超越了传统 ' 提示词工程 ' 的范畴，能实现效率的指数级提升。"

他结合实战案例拆解了具体方法：首先要提供宏观上下文，通过输入整体方案设计文档和模块指令，让 AI 建立对任务的全局认知；其次善用 @指令引入项目既有文件，无论是项目结构、代码风格还是技术文档，都能让 AI 生成的代码更贴合项目实际。现场他展示了经典案例：将一段冗余的 if 逻辑代码输入 Cursor 后，成功引导 AI 采用 "策略模式" 重构，大幅减少了 if/else 判断。

![CursorC__2.jpg](https://s2.loli.net/2025/09/20/1hwbzoiJKELfPHe.jpg)

"规则化与自动化是团队协作的关键。" 他补充道，利用顶部 "Rules" 功能定义开发规范后，AI 生成代码时会自动遵循标准，后期修改成本降低 40% 以上。谈及未来，他期待通过集成 Copilot 等工具，打通设计、开发、测试全链路，实现 "代码自生长" 的自动化编程愿景。　　

### 小橘子：一个安卓App的诞生——独立开发者的Cursor实践与思考

![.jpg](https://s2.loli.net/2025/09/20/gwLNxeOYA5FVMt6.jpg)

拥有十年后端开发经验的小橘子，以 "一个安卓 App 的诞生" 为主题，分享了从迷茫到通透的实践历程。他首先给全场泼了盆 "冷水"："很多人对 AI 编程抱有股市新手式的暴富幻想，但软件开发从来不是一蹴而就 ——80% 的工作是沟通和解决问题，而非敲代码。"

这种认知源于他开发 "个人手机使用时长追踪 App" 的经历。这个要求 "本地统计数据、绝不碰云服务" 的项目，让他完成了深刻的资产观念转变："代码是随时可以删除替代的，真正的资产是需求文档、设计方案、开发经验和知识库。"

![APP.jpg](https://s2.loli.net/2025/09/20/8wTGikzrVWacQO9.jpg)

他详细拆解了开发流程：先将 "统计手机使用时长" 的一句话需求，拆解为包含交互逻辑、数据指标的详细 PRD 文档；用 ChatGPT 生成初步 UI 设计图后，为 Cursor 准备了界面需求、数据结构、技术栈选型等全套上下文文档；即便完全不熟悉安卓开发，仍依赖 Cursor 生成核心代码，并修复了上百个编译与逻辑错误 —— 不过首次尝试因经验不足，耗尽了 20 美元的模型调用额度。

> Q&A
>
> Q:如何管理长对话上下文？
>
> A:当对话过长时，将手动进行“指令压缩”，总结已实现功能、未实现功能和当前问题，作为一个新的上下文起点。
>
> Q:如何应对AI修改错误？
>
> A:利用版本控制（Git）作为保险。在AI修改前，要求其先列出计划修改的文件清单进行确认，以限制其修改范围。
>
> Q:开发中更愿意选择什么模型？
>
> A:主要使用Claude 3 Sonnet+，Opus在“思考”层面表现更佳，但成本较高。

### Cursor 官方：BugBot 的质量守护逻辑

![Aman.jpg](https://s2.loli.net/2025/09/20/deSKa3DRuLGnriU.jpg)

中场休息前，Cursor 产品团队成员 Aman 通过视频连线带来 BugBot 专题分享。

他直指工具核心价值："传统 Linter 能查语法错误，但 BugBot 专攻逻辑漏洞、边界条件遗漏和竞争条件这类隐性问题，在代码审查阶段就能省下大量排障时间。

"为何选择在 PR 阶段启用 BugBot？"

Aman 解释："这是代码合并前的最后一道关卡，能最有效地阻止缺陷流入生产环境。" 他透露了一个有趣的细节："BugBot 在内部测试时就频繁发现有效问题，早期版本甚至揪出了一个导致自己下线的 bug。"

关于未来规划，Aman 明确了三大方向：优化模型减少误报，提升高价值 bug 的识别率；新增严重性评级、智能总结等功能；让 "Cursor 一键修复" 流程更无缝自动化。

"最让团队自豪的反馈，不是用户夸功能全，而是大家公认 BugBot 发现的 bug 质量极高。" 

### 程峰：Cursor在办公场景的高效实践

![.jpg](https://s2.loli.net/2025/09/20/Ctk2flcvFixujND.jpg)

**程峰（西安勤人信息科技创始人）**从最初质疑并卸载，到因项目压力无奈重拾，最终通过解决实际难题（反编译小程序、通过截图对接复杂API）而彻底信服，并总结出 *“ 用 Cursor 创造工具 ”* 的新范式。他认为，现在是创造力生产力的时代，开发者应从关注底层语法中解放出来，专注于 *“ 创造工具 ”* 来解决问题。他将此定义为 *“ 第五次工业革命 ”*。

在一些项目中，几乎所有项目均由他个人晚间使用 Cursor 完成。

- C++ 抖音直播助手：在不了解 C++ 的情况下，根据 Cursor 的逐步指导，成功开发了一款能抓取直播间弹幕、进行语音合成与回复的桌面应用。

- PPT 生成工具：本想让 Cursor 写 PPT，但 AI 回应 *“ 不能直接做，但可以写一个生成PPT的工具 ”*，这个经历让他思维模式发生转变。

- 跨国项目国际化（Java）：利用 Cursor 快速完成多语言翻译和文件替换工作。

- 策划案与报价单生成平台：输入一份结构化的 Word 需求文档，AI 可自动生成完整的项目策划书，乃至包含详细工时和报价的 Excel 表格。

- C 盘清理工具：因不满市面上的付费软件，自己动手用 Cursor 写了一个桌面应用，用于分析和清理 C 盘大文件。

- 项目资料管理系统：为解决员工离职资料交接不清的问题，开发了能智能扫描全盘、识别代码和重要文件，并用AI分析其用途的内部工具。 

> Q&A
>
> Q:如何复刻UI界面？
>
> A:复刻界面直接截图效果不佳。更好的方式是让AI分析UI的设计要点（配色、布局），或提供Figma链接，或给AI一篇关于设计趋势的文章作为参考。
>
> Q:AI时代的人才观是怎样的？
>
> A:他发现有经验的老员工对AI工具有抵触心理。现在招聘更倾向于没有“技术执念”的新人或大学生，认为他们更能适应新的开发模式。效率上，一个会用Cursor的新人可能超越多年的传统工程师。
>
> Q:测试变难该如何解决？
>
> A:承认AI生成大量代码后测试变难。他的方法是让AI编写测试用例，并采用Playwright等工具进行自动化测试。当AI犯错时，果断撤销，并确保数据库表结构等基础设计的正确性。

正如雅芳在开场时所说："这场相遇，是 Cursor 中国社区生长的第一步。" 而对于每一位参会者而言，这更是一场从 "使用 AI 工具" 到 "与 AI 共生" 的认知觉醒之旅。

![.jpg](https://s2.loli.net/2025/09/20/YzleW8N6hJEnLxQ.jpg)

本次会议令人非常充实，也是受益匪浅，对于我搁置了很长时间的CStudy项目和智能仓库机器人有了很大的启发，这两个或许会单独开出一个栏目来略微讲述，但是现在目前处于初代版本，想要体验的可以移步本人GitHub，项目描述贴在下面。

- 项目名称：[CStudy](https://github.com/shanchuann/CStudy.git)
- 项目描述：这是一个C语言编程练习项目，包含了多个具有挑战性的练习题目，涵盖了基础的编程知识，以及C语言部分高级主题。每个练习都提供了完整的实现代码、详细的实现提示和预期输出结果。这些练习从简单到复杂，逐步深入，帮助学习者掌握C语言的高级特性和编程技巧。项目结构清晰，每个练习都包含main.c（实现代码）、hints.txt（实现提示）和expected.txt（预期输出）三个文件，便于学习和参考。通过这些练习，学习者可以深入理解C语言的核心概念，提高编程能力，并为后续的系统编程和底层开发打下坚实基础。
- 项目链接：https://github.com/shanchuann/CStudy.git

- 需求：目前项目基本框架搭建完成，但是因为一些错误导致文件混乱，同时题目并不完整，答案审查仍存在问题。



- 项目名称：[shanchuann-Warehouse-Question-Answering-Robot](https://github.com/shanchuann/shanchuann-Warehouse-Question-Answering-Robot)
- 项目描述：这是一个基于 LangChain、FAISS 和 Ollama 开发的智能问答机器人，它采用 Streamlit 构建了一个支持中英文双语切换的用户界面。系统能够自动加载和处理 Markdown 文档，通过文本智能分块和向量化存储技术实现高效的文档检索和问答功能。项目具备完善的会话管理功能，包括对话历史保存、导出等，同时在性能方面实现了向量存储持久化、增量更新、批量处理等优化。作为一个可扩展的知识库问答系统，它不仅可以用于特定仓库的文档问答，还可以通过修改配置和代码来支持其他类型的文件和不同领域的知识库构建。
- 项目地址：https://github.com/shanchuann/shanchuann-Warehouse-Question-Answering-Robot.git
- 需求：这个项目来自字节跳动AI方向的青训营，目前基本内容已经实现，但是前端代码并不美观，对于其中提到的更改其中的文件达到个人知识库并未测试，可能需要优化。
