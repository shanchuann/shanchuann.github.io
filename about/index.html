下午常常一个人在西安南郊的工位坐着，写 reactor、读 STL 源码、调日志库；晚上把当天的修补写成博客。 做的项目不一定大，但每一行都得能讲清楚为什么这么写。

How I Work — three rules I keep coming back to.

§ 02
01 Write the problem first 先把问题写清楚，再写代码。能写清楚的，往往已经做完一半。
02 Trust the tool, keep the judgment 信任工具，但不让工具替你思考 —— AI 给我节奏，我给它判断。
03 One thing at a time 一次只做一件事，做到能讲清楚为止。讲不清楚的，就还没做完。
04 Read before writing 动手前先把现有代码读一遍。在别人的逻辑上修补，比自己另起一摊要诚实得多。
05 Ship small, often 小步、频繁、可回滚。先让一条最窄的路跑通，再去拓宽 —— 比一次性铺好高速路靠谱得多。
06 Leave the place tidier 改动结束前，把顺手发现的小坑填一下。不是大重构，只是别让下一个看到这段代码的人骂出声。

HyperTicket

高性能票务预约系统 · core developer · 2025.12 — 2026.06

在单机上把"几万个连接"压成"一个事件循环" —— 主从 Reactor + one loop per thread + 业务线程池；下单与取消放进事务里，靠 SELECT … FOR UPDATE 行锁根治超卖。已在 Linux 完成完整部署与压测。

真正学到的不是网络模型，是"读一遍 InnoDB 锁文档"和"用 wrk 压一晚上"的耐心 —— 这个项目教会我把每一条事务边界都写下来。

Visualization for Hexo

博客可视化管理工具 · full-stack · 2026.01 — 2026.05

ChronoLite

轻量级异步日志库 · solo · 2026.02 — 2026.04

为高并发服务端和资源受限环境写的日志库 —— 双缓冲交换 + 后台写线程，业务线程不等磁盘 IO；纳秒时间戳、文件大小与时间双重轮转、过期自动清理。printf 与流式两种 API；CMake 静态/动态库；已嵌进 HyperTicket 等项目当基础组件。

What I reach for.

从 C 开始，然后 C++11/17/20。STL 容器、智能指针、移动语义、模板、lambda 这些我用着不慌。Linux 系统编程是顺着 C++ 这条线自然走过来的 —— 内核一直在问我答不上的问题，我得回去补课。最近的练手清单：用 std::ranges 重写一遍 STL 算法、用 coroutine 抽象 epoll、用 perf 看自己写的反应器到底慢在哪。

C++11 / 17 / 20 STL · RAII · Move semantics Templates · Lambda Linux · IPC · Signals · GDB
Since 2024— 项目真正落地的地方 · where my projects live.

Linux 下的进程/线程模型、IO 多路复用、事件驱动框架。TCP/IP 四层和 HTTP/HTTPS 都吃过亏才搞明白 —— 粘包、心跳、自定义协议这些是 HyperTicket 教我的。MySQL 的事务隔离与 InnoDB 锁也是这一路顺出来的。Redis 主要用来兜热点和做幂等键；这一块我还在补，缓存击穿/穿透/雪崩这些课本概念在生产里只是冰山一角。

Epoll · Reactor · Thread pool TCP/IP · HTTP/HTTPS MySQL · ACID · InnoDB locks Redis · Cache patterns
Since 2025— 每天用，慎用 · daily but cautiously.

Claude Code 是日常同事。LangChain 用来串调用与外部工具，Ollama 在本地跑小模型，Prompt 是当作"接口契约"在维护。我会让 AI 帮我读日志、复盘 bug、生成脚手架 —— 但所有架构决策和最终判断留给人。Hexo Viz 里的多模型助手就是按这个思路写的：不让 AI 替你提交，先让它写出 Diff，你逐行点头再走。

Claude Code · Copilot LangChain Ollama · Local LLMs Prompt engineering
Always— 决定项目能不能活下来的"无聊"部分。

Git 用得多就总会练顺。CMake、Gradle 跨平台搭项目；GitHub Actions 把构建、测试、发布串起来；Docker / Docker Compose 是给同事跑起来最稳的方式；GDB 是真正出问题时的伙伴。我习惯把每个项目的"一行起步指令"写进 README ——docker compose up 就能跑的项目，比贴十张架构图都有说服力。
